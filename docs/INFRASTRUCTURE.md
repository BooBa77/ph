# Инфраструктура PeakHunter

Документ описывает **где всё живёт и как это обслуживать**: сервер, прод-стек,
маршрутизацию, доступы, секреты и деплой. Про библиотеки и код — в `stack.md`.

Все факты здесь проверены на живой системе, а не переписаны из планов.
Если что-то разошлось с реальностью — правьте документ, он источник правды
для «как устроено», а `package.json` и `docker-compose*.yml` — для версий.

---

## 1. Общая схема

```
Браузер
  │  https://ph.booba.fvds.ru
  ▼
Хостовый nginx на сервере  (TLS, Let's Encrypt)
  │  /      → 127.0.0.1:8081
  │  /api/  → 127.0.0.1:3001/api/
  ▼
Docker на том же сервере
  ├── ph-prod-frontend-1   ghcr.io/booba77/ph-frontend:latest  (nginx + статика SPA)
  ├── ph-prod-backend-1    ghcr.io/booba77/ph-backend:latest   (NestJS, :3000 внутри)
  └── ph-prod-postgres-1   postgis/postgis:16-3.5-alpine       (PostgreSQL + PostGIS)
        └── том ph_postgres_data
```

**Все контейнерные порты слушают только `127.0.0.1`.** Наружу смотрит
исключительно хостовый nginx — он же терминирует TLS. Поэтому в образе
фронтенда (`nginx.frontend.conf`) прокси на `/api` нет и быть не должно:
до контейнера такие запросы не доходят.

| Что | Значение |
|---|---|
| Сервер | `booba.fvds.ru`, Ubuntu 24.04.4 LTS |
| Пользователь | `dl_admin_tsy` |
| SSH-порт | `23451` |
| Прод-каталог | `/home/dl_admin_tsy/ph-prod` |
| Домены | `ph.booba.fvds.ru` (наш), `u40ta.booba.fvds.ru` (другой проект) |
| Реестр образов | `ghcr.io/booba77/ph-backend`, `ghcr.io/booba77/ph-frontend` |

На том же сервере работает **второй, не наш проект** — `u40ta-prod`
(каталог `/home/dl_admin_tsy/u40ta-prod`, порты 3000/5432/8080).
Не путать при правках nginx и портов.

## 2. Файлы на сервере

`/home/dl_admin_tsy/ph-prod/` содержит ровно два файла:

| Файл | Что это | Версия в репозитории |
|---|---|---|
| `docker-compose.yml` | прод-стек | `docker-compose.prod.yml` |
| `.env` | секреты и настройки, права `600` | **не версионируется** |

Имена файлов на сервере и в репозитории **различаются намеренно**: в корне
репозитория `docker-compose.yml` — это dev-стек, путать их нельзя. На сервере
файл называется `docker-compose.yml`, чтобы `docker compose` находил его без
флага `-f`. При изменении прод-конфига в репозитории его нужно скопировать
на сервер — иначе копии разъедутся.

Хостовый nginx: `/etc/nginx/sites-available/ph.booba.fvds.ru` (симлинк в
`sites-enabled/`), версия в репозитории — `nginx.host.conf`.

## 3. Переменные окружения

Значения живут только в `.env` на сервере. В репозитории их нет — там
перечислены лишь имена:

```
POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB
DATABASE_URL              # рантайм: роль с правом только на DML
MIGRATION_DATABASE_URL    # миграции: роль с правом на DDL
JWT_ACCESS_SECRET, JWT_ACCESS_EXPIRES_IN, REFRESH_EXPIRES_DAYS, COOKIE_SECURE
EMAIL_SMTP_USER, EMAIL_SMTP_PASSWORD, EMAIL_SMTP_FROM
```

Важная деталь: **`.env` сам в контейнер не попадает.** Compose использует его
только для подстановки `${...}`. Чтобы переменные оказались внутри, у сервиса
должен быть `env_file: .env` — он есть у бэкенда. Без него `JWT_ACCESS_SECRET`
не доезжает до приложения, и оно уходит в бесконечный рестарт.

Для SMTP mail.ru нужен **пароль для внешних приложений**, и `EMAIL_SMTP_FROM`
обязан совпадать с `EMAIL_SMTP_USER`, иначе mail.ru отвечает
`501 sender address must match authenticated user`.

## 4. Роли в базе

Заведены три роли — по журналу `backups/2026-10-04-security-and-prod.md`:

| Роль | Права | Кто использует |
|---|---|---|
| `ph_owner` | владелец БД, суперпользователь | ручные операции, `CREATE EXTENSION` |
| `ph_migrator` | DDL | `npm run migration:run`, `MIGRATION_DATABASE_URL` |
| `ph_app` | DML | рантайм приложения, `DATABASE_URL` |

Расширения `postgis` и `uuid-ossp` создаются **заранее** от `ph_owner`:
у `ph_migrator` нет прав на `CREATE EXTENSION`, а у `ph_app` тем более.

`sync-db.bat` (локальный, в репозиторий не входит) тянет прод-базу в dev через
SSH-туннель `ssh -N ph-db-tunnel`.

## 5. Доступ по SSH

SSH-порт нестандартный — `23451`, настройки в `~/.ssh/config` на рабочей машине:

```
Host booba
  HostName booba.fvds.ru
  User dl_admin_tsy
  Port 23451
```

Ключей два, и это разделение важное:

| Ключ | Парольная фраза | Для чего |
|---|---|---|
| `id_ed25519` | **есть** | личная работа: вы вводите фразу руками |
| `id_ph_deploy` | нет | автоматизация: команды из скриптов и от агента |

Ключ с фразой нельзя использовать неинтерактивно — ssh не может её спросить и
после `Server accepts key` молча падает с `Permission denied`. Для команд без
человека нужен второй ключ:

```powershell
ssh -i "$env:USERPROFILE\.ssh\id_ph_deploy" -o IdentitiesOnly=yes -o BatchMode=yes booba "hostname"
```

Публичная половина `id_ph_deploy` лежит в `~/.ssh/authorized_keys` на сервере.
Отозвать доступ — удалить эту строку.

## 6. Деплой

```powershell
git push                                    # 1. запускает GitHub Actions
# 2. дождаться зелёного прогона: https://github.com/BooBa77/ph/actions
```

```sh
# 3. на сервере
ssh booba
cd /home/dl_admin_tsy/ph-prod
docker compose pull && docker compose up -d
```

**`pull` без `up -d` ничего не меняет.** `pull` только скачивает образ;
контейнер продолжает работать на старом, пока его не пересоздадут. На этом
прод уже один раз застрял: в сентябре 2026 он месяц крутил образ без
авторизации, потому что выполнялся только `up -d` без `pull`. Обратная
ошибка — только `pull` без `up -d` — выглядит так же безобидно и даёт тот же
результат.

Проверка после деплоя:

```sh
curl -s https://ph.booba.fvds.ru/api/health
# ожидаем {"status":"ok","db":"ok",...}
```

## 7. Грабли

| Что | Почему |
|---|---|
| `pull` не пересоздаёт контейнеры | Нужен `up -d`. И наоборот: `up -d` не скачивает образ |
| `.env` не попадает в контейнер сам | Нужен `env_file`/`environment`, иначе переменных внутри нет |
| `.gitignore` не спасает уже отслеживаемый файл | Нужен `git rm --cached`. Именно так утёк пароль прод-БД |
| `CREATE EXTENSION` требует суперюзера | Миграции идут под `ph_migrator` — расширения создавать заранее |
| TypeORM пишет имя миграции из свойства `name` класса | У `InitAuth` имя `InitAuth1727000000000` не совпадает с таймстампом файла. Переименовать класс без `UPDATE migrations` нельзя — миграция выполнится повторно |
| `trust` в `pg_hba.conf` образа postgres | Действует только для соединений **изнутри** контейнера; пароль надо проверять снаружи |
| Порты слушают `127.0.0.1` | Снаружи виден только nginx. Прямой доступ к БД — через `ssh -N ph-db-tunnel` |

## 8. Чего в репозитории нет

| Не версионируется | Почему |
|---|---|
| `.env` | секреты |
| `sync-db.bat` | локальный скрипт с паролем прод-БД |
| `start-work.bat`, `end-work.bat` | инструменты конкретной машины |
| `backups/`, `docs/*` кроме `.md` | локальные журналы и шпаргалки |

Правило простое: **всё, что содержит секреты или привязано к одной машине, —
вне репозитория.** Всё, что описывает проект (включая прод-конфиги без
секретов), — внутри.
